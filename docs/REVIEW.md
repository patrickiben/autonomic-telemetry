# Current release scope

Version 2.4.0 restores the original integrated multivariate architecture beneath the immersive canvas. The shared `multivariate-1` engine combines the original nominal HR/RMSSD/respiration/turbulence/EEG/SDNN terms, bounded autocorrelation/entropy and lead–lag modifiers, and separate causal-surprise onset detection. The scale returns to the original one-sided zero-reference convention. Fixed profile weights, actual pulse SDNN, causal prediction, and quality/freshness handling correct identified prototype defects. The [capability matrix](CAPABILITIES.md) distinguishes executable restoration from remaining input requirements.

Advanced Signal Lab now replays the same integrated engine, automatically following its recording cursor or opening an exported main-page analysis session. It also retains the three-signal comparison model and independent recording research lenses. References can be explicitly saved/opened; no automatic personal-data persistence is added. The original user-provided private prototype remains untouched.

Muse provides quality-gated EEG beta/alpha, pulse RMSSD, actual pulse SDNN, and fallback pulse rate; Hume provides preferred reported HR. The current bridge does not derive respiratory rate. With all four available wearable channels, 85 of the original 100 nominal weight points are represented and normalized once. Losing a reference channel holds the estimate. These are experimental physiological-pattern calculations; software and transport tests do not establish physiological accuracy. Work retains its optional sustained cue; Rest retains independent breathing guidance and a within-profile trend.

Hume passed a bounded physical transport test on one Band V2: 84 validated nonzero responses over 90 seconds after acquisition, a longest gap of three seconds, and verified teardown. Its narrow start command renews every 20 seconds. One Athena Muse S passed a 40.3-second raw-stream test with eight EEG channels, four optical channels, and acceleration, without malformed packets, stale intervals, or adapter errors, followed by clean teardown. Both live sources also reached the canvas through the bridge in a mobile-sized desktop Chromium viewport; actual iPhone performance was not tested. These results do not establish physiological accuracy, indefinite operation, or universal firmware compatibility. See [Devices](DEVICES.md), [Methods](METHODS.md), and the [current validation notes](VALIDATION.md).
